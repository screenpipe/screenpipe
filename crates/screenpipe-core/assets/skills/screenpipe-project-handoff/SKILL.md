# project handoff

Identify the project and intended recipient. Use screenpipe-api to recover recent work, decisions, and artifact references; inspect current project files or connected systems when available to verify what still applies.

Give the recipient the purpose, verified current state, where to continue, blockers, and concrete next steps. Distinguish merged or delivered work from drafts, tests, and intentions. Name owners and dates only when supported; otherwise leave them open.

Include source links and exact artifact locations that the recipient can access. Remove unrelated conversations, credentials, and private customer details. Draft in chat unless another destination is requested. A handoff request alone does not authorize sending it, granting access, or assigning work.
