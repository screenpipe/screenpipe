# Saved narration retrieval implementation plan

<!-- doc-covers: none -->

Goal: satisfy SCR-1195 within PR #7947. Keep the focused recording storage and capture paths intact.

Architecture: GET /focused-recordings/:id/audio returns metadata ordered by stream start, stream ID, and sequence, plus recorded intervals. GET /focused-recordings/:id/audio/:chunk returns the original container fragment with its MIME type. Concatenate chunks in sequence within each stream; never concatenate independent streams across pauses.

1. Add an HTTP regression that saves narration, submits, closes the file database, reopens it, and retrieves exact bytes and interval metadata. Confirm the missing route fails.
2. Add metadata and single-chunk database reads, authorized handlers, and routes. Preserve history checks, pipe restrictions, vault/auth middleware, and the existing audio exemption from text/image privacy policy. Return no-store on reads.
3. Run the endpoint regression and relevant DB tests, format changed Rust files, and review the diff. Document the supported API and validation in the existing PR.

Tests must catch missing reads, reordered chunks, lost pause boundaries, cross-recording chunk access, expired history, and unchanged audio under text/image privacy. No transcription is required. No UI or discovery integration is in scope.

Review finding: allow only the two narration GET/HEAD paths in search-only mode; exercise allowed reads and denied mutations under the suspended middleware. Existing focused DB suite: 9 passed.

Policy audit: protected_reads_enabled identifies a text/image read adapter, not an audio restriction. Existing audio exemptions apply. Configure privacy before constructing that adapter in tests; configuration alone does not change an existing raw database handle.
