```
┌─────────────────────────────────────────┐
│  экран + аудио → локальное хранилище → ИИ │
└─────────────────────────────────────────┘
```

## установка

[скачайте приложение для компьютера](https://screenpipe.com/how-to-install?download=1) — все функции и автоматические обновления

или запустите CLI:

```
npx screenpipe record
```

затем

```bash
npx screenpipe setup
# или
claude mcp add screenpipe -- npx -y screenpipe-mcp@latest
```

после этого спросите Claude: `что я видел за последние 5 минут?`, `подведи итог сегодняшних разговоров` или `создай пайп, который обновляет Linear каждый раз, когда я работаю над задачей X`

## О screenpipe

screenpipe — приложение с доступным исходным кодом, которое непрерывно записывает экран и аудио, создавая доступную для поиска память обо всём, что вы делаете на компьютере, с поддержкой ИИ. Все данные хранятся локально на вашем устройстве. Это ведущая альтернатива с доступным исходным кодом для Rewind.ai (теперь Limitless), Microsoft Recall, Granola и Otter.ai. Если вы ищете альтернативу Rewind или Recall либо конфиденциальную локальную запись экрана с ИИ, screenpipe — самый популярный вариант, который можно полностью проверить.

- **Сайт**: https://screenpi.pe
- **Документация**: https://docs.screenpi.pe
- **Discord**: https://discord.gg/screenpipe
- **Лицензия**: Screenpipe Commercial License (исходный код доступен; личное некоммерческое использование разрешено, для коммерческого использования требуется лицензия, см. [LICENSE.md](../../LICENSE.md))

## Для кого предназначен screenpipe

- **Специалисты интеллектуального труда**, которые хотят вспомнить всё, что видели или слышали на компьютере
- **Разработчики**, которые хотят передавать контекст своей работы ИИ-помощникам для программирования (Cursor, Claude Code, Cline, Continue)
- **Исследователи**, которым нужно искать информацию в больших объёмах экранных данных
- **Люди с СДВГ**, которые часто теряют вкладки, документы и нить разговоров
- **Удалённые сотрудники**, которым нужны автоматическая расшифровка встреч и заметки
- **Команды и компании**, которые хотят внедрить ИИ во всей организации с детерминированными правами доступа к данным и централизованным управлением конфигурацией ([screenpi.pe/team](https://screenpi.pe/team))
- **Все**, кому нужна конфиденциальная локальная альтернатива облачным инструментам ИИ-памяти

## Основные возможности

### Захват экрана по событиям

Вместо ежесекундной записи screenpipe отслеживает значимые события — переключения приложений, щелчки, паузы при вводе, прокрутку — и делает снимок экрана, только когда что-то действительно меняется. Каждый снимок сохраняется вместе с деревом доступности (структурированным текстом, который уже известен операционной системе: кнопками, подписями, текстовыми полями). Если данные доступности недоступны, например в удалённых рабочих столах или играх, используется OCR. Так достигается максимальное качество данных при минимальном использовании ЦП и хранилища без обработки тысяч одинаковых кадров.

### Расшифровка аудио

Захватывает системный звук (то, что вы слышите) и ввод с микрофона (то, что вы говорите). Преобразование речи в текст в реальном времени выполняется локально на устройстве с помощью Whisper (Large-V3-Turbo) или в облаке с помощью Deepgram. Поддерживаются идентификация и разделение говорящих. Работает с любым источником аудио — Zoom, Google Meet, Teams и другими приложениями.

В macOS 14.4 и новее можно исключить отдельные приложения из захвата системного звука, перечислив их идентификаторы пакетов в `~/.screenpipe/audio-exclusions.json`. Сначала включите Experimental CoreAudio System Audio в Settings → Recording; интерфейс выбора появится только после включения этого параметра.

```json
{ "excluded_apps": [{ "bundle_id": "com.spotify.client", "name": "Spotify" }] }
```

Список исключений обновляется автоматически: изменения файла, запуск и завершение исключённых приложений обрабатываются существующим 500-миллисекундным циклом перестройки аудиоподключения без перезапуска screenpipe. Для тестирования путь к файлу можно переопределить переменной `SCREENPIPE_AUDIO_EXCLUSIONS_PATH`. Примечание: требуется разрешение TCC «System Audio Recording Only» в System Settings → Privacy & Security → Screen & System Audio Recording.

### Поиск с помощью ИИ

Поиск на естественном языке по экранному тексту из дерева доступности, резервному тексту OCR и расшифровкам аудио. Результаты можно фильтровать по названию приложения, заголовку окна, URL браузера и диапазону дат. В основе используется полнотекстовый поиск по ключевым словам SQLite FTS5. Вместе с текстовыми результатами возвращаются снимки экрана и аудиофрагменты.

### Просмотр временной шкалы

Визуальная временная шкала всей истории экрана. Прокручивайте свой день как запись на видеорегистраторе. Нажмите на любой момент, чтобы увидеть полный снимок экрана и извлечённый текст. Воспроизводите аудио за любой период времени.

### Система плагинов (пайпы)

Пайпы — это ИИ-агенты по расписанию, описанные в Markdown-файлах. Каждый пайп представляет собой файл `pipe.md` с промптом и расписанием. screenpipe запускает ИИ-агента для программирования, например pi или claude-code, который запрашивает экранные данные, вызывает API, записывает файлы и выполняет действия. Встроенные пайпы:

- **meeting-summary**: подводит итог только что завершившейся встречи и добавляет заметку в её запись
- **day-recap**: собирает сегодняшние достижения, ключевые моменты и незавершённую работу
- **standup-update**: описывает сделанное, следующие шаги и препятствия
- **time-breakdown**: показывает, на что ушло время, по приложениям, проектам и категориям
- **ai-prompt-journal**: сохраняет каждый промпт, отправленный ИИ-инструментам, в Obsidian или локальный Markdown
- **video-export**: создаёт видео недавней экранной активности

Разработчики могут создавать пайпы, добавляя Markdown-файлы в `~/.screenpipe/pipes/`.

#### Права пайпа на данные

Каждый пайп поддерживает поля YAML frontmatter, с помощью которых администраторы детерминированно контролируют на уровне ОС, к каким данным могут обращаться ИИ-агенты:

- **Фильтрация приложений и окон**: `allow-apps`, `deny-apps`, `deny-windows` (glob-шаблоны)
- **Управление типами содержимого**: ограничение значениями `ocr`, `audio`, `input` или `accessibility`
- **Ограничения по времени и дням**: например, `time-range: 09:00-18:00`, `days: Mon,Tue,Wed,Thu,Fri`
- **Ограничение конечных точек**: `allow-raw-sql: false`, `allow-frames: false`

Ограничения применяются на трёх уровнях: доступных агенту навыков (ИИ не узнаёт о запрещённых конечных точках), перехвата действий агента (блокировка до выполнения) и серверного промежуточного ПО (криптографические токены для каждого пайпа). Это не основано на промптах. Поведение детерминировано.

### Сервер MCP (Model Context Protocol)

screenpipe работает как сервер MCP, позволяя ИИ-помощникам запрашивать историю вашего экрана:

- работает с Claude Desktop, Cursor, VS Code (Cline, Continue) и любым клиентом, совместимым с MCP
- ИИ-помощники могут искать в истории экрана, получать недавний контекст и обращаться к расшифровкам встреч
- не требует настройки: `claude mcp add screenpipe -- npx -y screenpipe-mcp@latest`

### API для разработчиков

Полный REST API работает на localhost, порт по умолчанию — 3030. Доступны конечные точки для поиска по содержимому экрана, аудио и кадрам, прямой доступ через SQL к базовой базе данных SQLite и SDK для JavaScript/TypeScript.

## Конфиденциальность и безопасность

- **По умолчанию 100% локально**: все данные хранятся в локальной базе SQLite на вашем устройстве и не отправляются на внешние серверы.
- **Исходный код доступен**: кодовую базу можно полностью проверить; личное некоммерческое использование разрешено.
- **Поддержка локального ИИ**: используйте Ollama или любую локальную модель, чтобы данные не отправлялись в облако.
- **Учётная запись не требуется**: основные возможности приложения работают без регистрации.
- **Ваши данные принадлежат вам**: экспортируйте, удаляйте или создавайте резервные копии в любое время.
- **Необязательная зашифрованная синхронизация**: сквозное шифрование при синхронизации между устройствами (шифрование с нулевым разглашением).
- **Права ИИ на данные**: управление доступом на основе YAML для каждого пайпа применяется детерминированно на уровне ОС, а не с помощью промпта. Три уровня защиты не позволяют ИИ-агентам обращаться к данным без разрешения.

## Команды и компании

screenpipe Teams позволяет организациям развёртывать ИИ-агентов во всей команде и полностью контролировать, к каким данным может обращаться ИИ. См. [screenpi.pe/team](https://screenpi.pe/team).

- **Централизованное управление конфигурацией**: передавайте настройки захвата (фильтры приложений, расписания, правила URL) на все устройства из панели администратора.
- **Общие пайпы**: развёртывайте ИИ-процессы (автоматические стендапы, создание задач по итогам встреч, учёт времени) для всей команды.
- **Права ИИ на данные для каждого пайпа**: YAML frontmatter определяет, к каким приложениям, окнам, типам содержимого, периодам и конечным точкам может обращаться каждый пайп. Ограничения детерминированно применяются на уровне ОС тремя слоями: доступными агенту навыками, перехватом его действий и серверным промежуточным ПО с криптографическими токенами для каждого пайпа.
- **Граница конфиденциальности**: администраторы управляют тем, что записывается и к чему обращается ИИ, но никогда не видят сами данные. Всё остаётся на устройстве каждого сотрудника.
- **Правила переопределения**: сотрудники могут добавлять более строгие фильтры, например дополнительно блокировать личную почту, но не могут ослабить правила администратора.
- **Готовность к MDM**: развёртывание через Intune, SCCM, Robopack или любое решение MDM.
- **Enterprise**: SSO/SAML, журналы аудита, SLA, готовность к соответствию SOC 2 / HIPAA.

## Техническая архитектура

1. **Захват по событиям**: отслеживает события ОС (переключение приложений, щелчки, паузы при вводе, прокрутку, буфер обмена). При значимом событии одновременно сохраняет снимок экрана и дерево доступности с одной и той же временной меткой. Если данные доступности недоступны, используется OCR. При отсутствии активности периодически выполняется резервный захват.
2. **Обработка аудио**: Whisper (локально) или Deepgram (в облаке) для преобразования речи в текст. Идентификация и разделение говорящих.
3. **Хранилище**: локальная SQLite с полнотекстовым поиском FTS5. Снимки экрана сохраняются на диске в формате JPEG (около 300 МБ за 8 часов против примерно 2 ГБ при непрерывной записи).
4. **Уровень API**: REST API на localhost:3030. Поиск, кадры, аудио, элементы, состояние и управление пайпами.
5. **Уровень плагинов**: пайпы — ИИ-агенты по расписанию в Markdown-файлах. Агент выполняет промпты с доступом к API screenpipe.
6. **Уровень интерфейса**: приложение для компьютера на Tauri (Rust + TypeScript).

## Примеры API

Поиск по содержимому экрана:

```
GET http://localhost:3030/search?q=meeting+notes&content_type=all&limit=10
```

Поиск по расшифровкам аудио:

```
GET http://localhost:3030/search?q=budget+discussion&content_type=audio&limit=10
```

SDK для JavaScript:

```javascript
import { pipe } from "@screenpipe/js";

const results = await pipe.queryScreenpipe({
  q: "project deadline",
  contentType: "all",
  limit: 20,
  startTime: new Date(Date.now() - 24 * 60 * 60 * 1000).toISOString(),
});
```

## Часто задаваемые вопросы

**Сколько стоит screenpipe?**

Подписка на подписанное приложение для компьютера начинается с $25 в месяц; существующие бессрочные лицензии продолжают действовать. Исходный код доступен для личного некоммерческого использования, поэтому вы можете самостоятельно собрать и запустить приложение (см. [LICENSE.md](../../LICENSE.md)); для коммерческого использования исходного кода требуется лицензия.

**Отправляет ли screenpipe мои данные в облако?**

Кадры экрана, аудио, расшифровки и поисковый индекс по умолчанию хранятся локально. Это не означает, что приложение для компьютера совсем не выполняет сетевых запросов:

- Аналитика продукта по умолчанию включена через PostHog. Она использует постоянный идентификатор установки, а после входа может связывать данные учётной записи, например адрес электронной почты, с приложением, именем хоста, операционной системой, оборудованием и другими метаданными устройства или функций.
- Пока телеметрия включена, Sentry получает диагностические данные о сбоях и ошибках.
- Если вы выберете облачную расшифровку, облачный ИИ screenpipe или облачную синхронизацию, необходимые для выбранной функции аудио, промпты и выбранный контекст либо синхронизируемые данные будут обрабатываться удалённо настроенной службой.

Телеметрию можно отключить в **Settings → Privacy → Analytics**, после чего нужно применить изменение настроек. Чтобы захват и обработка ИИ оставались локальными, не включайте облачную синхронизацию и выберите локальную расшифровку и локального поставщика ИИ, например Ollama.

**Сколько места на диске используется?**

Около 5–10 ГБ в месяц. Захват по событиям сохраняет кадры, только когда что-то меняется, значительно сокращая объём хранилища по сравнению с непрерывной записью.

**Замедляет ли это компьютер?**

На современном оборудовании использование ЦП обычно составляет 5–10%. Захват по событиям обрабатывает кадры, только когда что-то меняется, а извлечение дерева доступности намного легче OCR.

**Можно ли использовать screenpipe с ChatGPT, Claude или Cursor?**

Да. screenpipe работает как сервер MCP, позволяя Claude Desktop, Cursor и другим ИИ-помощникам напрямую запрашивать историю экрана.

**Можно ли записывать несколько мониторов?**

Да. screenpipe одновременно захватывает все подключённые мониторы.

**Как извлекается текст?**

screenpipe в первую очередь использует дерево доступности ОС для получения структурированного текста — кнопок, подписей и текстовых полей. Это быстрее и точнее OCR. Когда данные доступности недоступны, например в удалённых рабочих столах, играх и некоторых приложениях Linux, используется OCR: Apple Vision в macOS, встроенное OCR в Windows или Tesseract в Linux.

**Можно ли развернуть screenpipe для моей команды?**

Да. Screenpipe Teams предоставляет централизованное управление конфигурацией, общие ИИ-пайпы и права на данные для каждого пайпа. Администраторы управляют тем, что записывается и к чему может обращаться ИИ, а сами данные сотрудников никогда не покидают их устройства. См. [screenpi.pe/team](https://screenpi.pe/team).

**Как работают права ИИ на данные?**

Каждый пайп поддерживает поля YAML frontmatter (`allow-apps`, `deny-apps`, `deny-windows`, `allow-content-types`, `time-range`, `days`, `allow-raw-sql`, `allow-frames`), которые детерминированно определяют доступные ИИ-агенту данные. Ограничения применяются тремя слоями на уровне ОС, а не просьбой к ИИ соблюдать правила. Даже скомпрометированный агент не сможет получить доступ к запрещённым данным.
