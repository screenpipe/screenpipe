## Environment and deviations

Run `qa-2728-20260908-4209`, 2026-09-08 UTC. Hermes Orchard 0.55.0, existing `aws-orchard` context, healthy `mac-mini` worker. Fresh clone of verified local `screenpipe-tahoe-no-sip-110gb-base`; this is a local base, not a claimed immutable OCI digest. Guest macOS 26.6.2 (25G83), SIP disabled, 8 CPU, 16384 MiB RAM, 110 GB disk, approximately 72 GiB free. Explicit CPU/RAM were used because discovered worker defaults were misconfigured. Guest display 1024×768; no host display or app was controlled.

The original signed app launched, but allowed TCC rows did not consistently match runtime permissions. The canonical `tcc-grant` workflow, native permission acceptance, guest-only removal of Finder metadata/ad-hoc re-signing, refreshed existing guest automation requirements, and one guest restart were needed. TCC also logged database-access errors before restart. Permissions and actual capture subsequently worked. This validates candidate functionality with a modified guest signing identity, not normal end-user TCC migration or notarization behavior.

Authentication used the verified existing internal QA account, a 600-second Clerk sign-in ticket in guest Safari, and the real app GET STARTED/browser callback. It did not test passwords, signup, or every login provider. No fake account seed or prewritten onboarding state was used. Free/no-card was selected; optional integrations were skipped.

The installed remote policy forced auto-update on and disabled its toggle. That policy was not bypassed. No update was applied; final app version remained 2.7.28. `/health` separately reports embedded engine version 0.4.50.
